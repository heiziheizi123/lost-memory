# CODE SELA UI 改版与移动端交互规范

> 项目：**《CODE SELA - 车祸现场男孩失踪案》**  
> 仓库：`heiziheizi123/lost-memory`  
> 文档状态：设计方向确认稿  
> 适用页面：案件档案、证据、推演、案件还原、设置及开场动画

---

## 1. 改版目标

本次改版将现有界面统一为“纸质案件档案”视觉，并加入调查助手 **SELA**。交互应让玩家感到自己正在翻阅卷宗、按下实体按键、整理证据并还原案件，而不是在填写普通网页表单。

核心目标：

1. 保留现有剧情、证据内容、答案判定、解锁条件和存档逻辑。
2. 建立统一的档案拟物视觉：米白纸张、深橄榄黑背景、暗红强调色、旧照片与印章。
3. 使用 SELA 的表情和动作反馈玩家当前操作。
4. 将主菜单制作成实体键帽样式。
5. 将“案件还原”制作成可拖拽、可点按的堆叠卡片。
6. 完整适配手机、平板和桌面端。
7. 支持触屏、鼠标、键盘与减少动态效果设置。

### 2.2 字体层级

- 所有可点击文字与背景的对比度应清晰可辨。

## 3. SELA 形象规范

### 3.1 基础造型

- 复古 CRT 电脑显示器头部，米白外壳、深橄榄屏幕。
- 顶部为两根细长 V 形天线。
- 面部仅使用简单线条显示眼睛与嘴，不采用真人五官。
- 身体穿直线剪裁的宽松西装与暗红领带。
- 不使用头发、睫毛、腮红、胸部曲线、裙装、肌肉等明显性别符号。
- 体型中性，动作友好但不过度幼态。
- 风格为手绘墨线、轻微排线与低饱和色块，和纸质档案界面一致。

### 3.2 表情状态

| 状态 | 面部与动作 | 触发场景 |
| --- | --- | --- |
| 微笑 | 竖线眼、小 V 形笑容、轻微挥手 | 初次进入、普通说明 |
| 思考 | 横向微眯眼、小平嘴、手托显示器下缘 | 拖拽卡片、系统分析 |
| 发现 | 圆眼、小开口、屏幕旁出现小亮点 | 获得证据、发现关联 |
| 疑问 | 一侧眼睛稍高、歪头、问号 | 信息不足、拖拽未达到阈值 |
| 警告 | 斜向严肃眼、直线嘴、暗红描边 | 关键选择、推演存在风险 |
| 推演成立 | 闭眼笑、确认印章或勾号 | 正确完成推演 |
| 失配 | 两眼方向略有差异、小波浪嘴 | 选择的证据互相矛盾 |
| 等待 | 缓慢眨眼、天线轻微摆动 | 玩家长时间无操作 |
| 读取 | 眼睛变为短扫描线 | 页面或档案加载 |
| 完成 | 温和笑容、合上卷宗 | 章节完成或保存成功 |

### 3.3 使用位置

- 桌面端：SELA 位于正文右侧助手栏，宽度约占页面的 `22%–28%`。
- 平板端：SELA 缩小为右下角半身助手，可展开消息纸条。
- 手机端：SELA 作为浮动头像或底部消息条出现，不长期占据正文宽度。
- SELA 不得覆盖答案、证据、按钮或拖拽区域。
- 连续提示之间至少间隔 `2s`，避免频繁跳动。

## 4. 主菜单键帽

菜单项：

- 案件档案
- 证据
- 推演或案件还原
- 设置

### 4.1 外观

键帽采用米白表面、深色侧壁、暗红文字，带轻微纸张或旧塑料质感。形状应接近老式打字机按键，但保持矩形以容纳中文。

### 4.2 状态

| 状态 | 位移 | 阴影 |
| --- | --- | --- |
| 默认 | `translateY(0)` | 外阴影，表现按键高度 |
| 悬停/聚焦 | `translateY(-1px)` | 外阴影稍增强 |
| 按下 | `translateY(3px)` | 外阴影变为内阴影 |
| 松手 | 先到 `translateY(-1px)`，再回到 0 | 恢复外阴影 |
| 当前页面 | `translateY(1px)` | 暗红底座或暗红描边 |
| 禁用 | 无位移 | 低对比度，不响应按压 |

建议时长：

- 按下：`70–90ms`
- 松手回弹：`160–220ms`
- 缓动：`cubic-bezier(.2,.8,.2,1.2)`

### 4.3 输入方式

- 使用 `button` 元素实现。
- 支持鼠标、触摸、Enter 和 Space。
- 不依赖 `:hover` 才能识别状态。
- 触控目标不得小于 `44 × 44px`。
- 通过 `:active` 或 `data-pressed` 控制下沉态。
- 发生 `pointercancel` 时必须恢复默认状态。

## 5. 案件还原卡片

### 5.1 默认状态

- “推理 1–9”以卡片堆形式显示。
- 未展开时只露出卡片编号、标题边缘和少量纸张层次。
- 当前已选择的卡片置于最前。
- 卡片内容可以包含证据缩略图、简短结论和关联编号。

### 5.2 开始选择

触发方式：

- 鼠标或触摸拖拽。
- 直接点击或轻触某张卡片。
- 键盘左右方向键切换，Enter 确认。

开始拖拽后：

1. 推理 1–9 展开。
2. 桌面端使用浅扇形或横向层叠。
3. 手机端使用纵向卡片轮播或底部抽屉，避免横向溢出。
4. SELA 切换为“思考”。
5. 当前接近选择位置的卡片略微抬升并放大。

### 5.3 拖拽成功

建议判定同时考虑距离和速度：

- 拖拽距离达到卡片尺寸的 `30%`，或
- 快速滑动速度达到 `0.45px/ms`。

成功后：

1. 目标卡片置顶。
2. 目标卡片缩放到 `1.03`，随后回到 `1`。
3. 后方卡片按顺序下沉 `4–6px`。
4. 后方卡片依次延迟 `25–40ms` 回弹。
5. SELA 切换为“发现”。
6. 页面下方更新该卡片对应的案件还原内容。

建议弹簧参数：

- stiffness：`260`
- damping：`24`
- mass：`0.85`

若不使用动画库，可使用近似缓动：

`cubic-bezier(.18,.89,.32,1.28)`

### 5.4 拖拽不足

当距离和速度均未达到阈值：

1. 卡片沿原路径归位。
2. 卡堆恢复原始次序。
3. 回弹时间约 `220–280ms`。
4. SELA 短暂显示“疑问”。
5. 不触发错误提示音，不扣除任何进度。

### 5.5 拖拽细节

- 使用 Pointer Events，同时支持鼠标、触控笔和触摸。
- 拖拽过程中为页面设置 `touch-action: none`，仅限制卡片区域。
- 拖拽开始后调用 `setPointerCapture()`。
- 处理 `pointerup`、`pointercancel` 和页面失焦。
- 卡片离开视口或操作被系统中断时必须安全归位。
- 拖拽时关闭文字选择和图片原生拖动。
- 不能只靠颜色表示当前选择，应同时使用层级、描边和编号。

## 6. 推演反馈

| 玩家操作 | 界面反馈 | SELA 状态 |
| --- | --- | --- |
| 收集证据 | 证据滑入档案夹，数量更新 | 发现 |
| 选择推演词语 | 当前空位和相关证据同时高亮 | 思考 |
| 提交推演 | 证据依次亮起并建立关联线 | 读取 |
| 推演存在矛盾 | 标出矛盾区域，保留玩家选择 | 失配 |
| 线索不足 | 提示需要核对的证据类型 | 疑问 |
| 推演成立 | 暗红印章落下，结论加入时间线 | 推演成立 |
| 保存成功 | 小型卷宗合拢动画 | 完成 |

错误提示必须说明问题所在，例如“这两条目击记录的时间无法同时成立”，避免只显示“回答错误”。

## 7. 开场动画

建议总时长 `8–12s`，首次进入自动播放，提供“跳过”按钮。继续游戏时直接进入存档。

建议镜头：

1. 黑屏与轻微环境声。
2. SELA 显示器出现扫描线并亮起。
3. SELA 从“读取”切换为“微笑”。
4. 卷宗被推入画面，封面出现游戏标题。
5. 暗红印章落下。
6. 卷宗打开并自然过渡到案件档案页面。

要求：

- 动画内容必须符合原剧情，场景天气、时间与证据不得凭空增加。
- 跳过按钮始终可见且触控区域不小于 `44px`。
- 设置中提供静音、跳过开场和减少动态效果。
- 页面不可在动画结束前阻塞存档读取。

## 8. 响应式布局

### 8.1 建议断点

| 范围 | 布局 |
| --- | --- |
| `≥ 1200px` | 桌面双栏：档案主体 + SELA 助手栏 |
| `768–1199px` | 平板布局：主体全宽，SELA 为悬浮半身助手 |
| `≤ 767px` | 手机单栏：底部键帽导航、卡片轮播、SELA 消息条 |
| `≤ 374px` | 紧凑手机：减少装饰边距，保证正文与触控尺寸 |

不要根据 User-Agent 判断设备，仅根据视口与输入能力调整。

### 8.2 手机端页面结构

从上到下：

1. 精简标题栏：案件编号、页面标题、进度。
2. SELA 消息条：头像、当前表情、单句提示，可折叠。
3. 当前任务或章节标题。
4. 证据或推演主体。
5. 主要操作按钮。
6. 固定底部键帽导航。

手机端底部导航：

- 使用安全区域：`padding-bottom: env(safe-area-inset-bottom)`。
- 四个键帽平均分配宽度。
- 单个键帽高度建议 `48–56px`。
- 文本过长时缩短为“档案 / 证据 / 还原 / 设置”。
- 底部导航不得遮挡正文，页面正文需预留相同高度。
- 键帽按下仍保留下沉与内阴影反馈。

### 8.3 手机端案件还原

- 默认显示当前卡片，后方露出 2–3 层卡边。
- 点击卡堆后，从底部展开“推理 1–9”纵向选择抽屉。
- 也允许左右拖拽切换卡片。
- 一次仅完整显示一张卡片，避免文字过小。
- 卡片宽度建议 `calc(100vw - 32px)`，最大不超过 `420px`。
- 卡片内部图片比例固定，正文可滚动但卡片本身不应超出屏幕。
- 拖拽方向与页面滚动冲突时：
  - 横向位移超过纵向位移 `1.2` 倍，判定为切换卡片；
  - 否则保留页面纵向滚动。
- 为不方便拖拽的玩家提供上一张、下一张和“选择”按钮。

### 8.4 横屏与平板

- 手机横屏时，卡片与详情可以改为左右双栏。
- 平板触控目标仍遵守最小 `44px`。
- 不因屏幕变宽而恢复依赖悬停的交互。
- iPad Safari 上避免使用只在鼠标环境可靠的 Drag and Drop API，统一使用 Pointer Events。

## 9. 动画与性能

### 9.1 动画原则

- 常规反馈：`120–240ms`。
- 页面切换：`240–400ms`。
- 开场动画除外。
- 动画尽量只修改 `transform` 和 `opacity`。
- 不在拖拽期间反复修改会触发布局的 `top/left/width/height`。
- 卡片阴影层数需控制，移动端同时显示的重阴影不超过 3 层。

### 9.2 减少动态效果

检测：

```css
@media (prefers-reduced-motion: reduce) {
  /* 取消弹簧、摇晃、扫描线和大幅位移 */
}
```

减少动态效果开启时：

- 键帽直接切换外阴影和内阴影，不回弹。
- 卡片使用淡入和层级切换，不做弹簧动画。
- SELA 表情直接切换，不摆动天线。
- 开场动画缩短为标题与卷宗封面静态过渡。

### 9.3 低性能设备

- 拖拽过程中只更新当前卡片的 transform。
- 后方卡片在松手后统一启动动画。
- 使用 `requestAnimationFrame` 合并指针移动更新。
- 图片设置明确宽高，避免加载时布局跳动。
- 装饰纹理应压缩并允许在窄屏关闭。

## 10. 无障碍与可操作性

- 所有交互均可使用键盘完成。
- 键帽和卡片必须有清晰的 `:focus-visible` 状态。
- 表情变化同时提供文字状态，例如“SELA：正在分析”。
- 重要信息不能只依靠 SELA 表情传递。
- 卡片使用适当的 `aria-label`，例如“推理 4：现场路况影响视线，当前选中”。
- 卡片次序变化后使用温和的 `aria-live="polite"` 提示。
- 音效与背景音提供独立开关。
- 支持 `prefers-reduced-motion`。
- 避免连续闪烁或高频屏幕故障效果。

### 11.2 ReasoningDeck 状态

```text
idle
→ expanding
→ dragging
→ committed
→ springing
→ idle

dragging
→ cancelled
→ restoring
→ idle
```

### 11.3 SELA 状态优先级

当多个状态同时触发时，优先级由高到低：

1. 警告
2. 推演成立
3. 失配
4. 发现
5. 思考 / 读取
6. 疑问
7. 微笑 / 等待

高优先级状态结束后再恢复当前页面的常驻状态，避免表情闪烁。

## 12. 验收标准

### 桌面端

- 键帽按下时明显下沉，并由外阴影切换为内阴影。
- 释放后有一次克制回弹。
- 9 张推理卡片可以展开、拖拽、置顶和归位。
- 选中卡片后，后方卡片依次下沉并弹簧回弹。
- SELA 至少实现六种可辨识表情。
- SELA 不遮挡任何核心操作。

### 手机端

- 320px 宽度下不出现水平页面滚动。
- 底部键帽导航不被 iPhone 安全区域遮挡。
- 所有触控目标至少为 `44 × 44px`。
- 单指可以滚动页面，也可以明确地横向切换卡片。
- 拖拽不足时卡片能够稳定归位。
- 点击操作可以替代所有拖拽操作。
- 键盘弹出、横竖屏切换、来电或系统手势中断后，不残留卡片拖拽状态。
- Android Chrome、iOS Safari 和 iPad Safari 可完成完整流程。

### 辅助设置

- 开启减少动态效果后仍可理解所有状态变化。
- 静音后不影响推演反馈。
- 键盘可以完成菜单导航和案件还原。
- 刷新页面后保持原有存档与进度。

## 13. 推荐实施顺序

1. 抽取全局颜色、字体、阴影和间距变量。
2. 改造纸质档案基础布局。
3. 实现桌面端与移动端键帽导航。
4. 接入 SELA 基础形象与表情状态机。
5. 实现案件还原卡堆的点击选择。
6. 增加 Pointer Events 拖拽、阈值判定和归位。
7. 增加后方卡片依次下沉与弹簧回弹。
8. 完成手机底部抽屉、横向滑动和安全区域。
9. 添加开场动画、跳过与减少动态效果。
10. 在不改变原剧情逻辑的前提下整合现有存档系统。
11. 完成桌面、手机和平板回归测试。

## 14. 不应改变的内容

- 不修改案件事实、人物关系、证据内容和正确答案。
- 不改变已有的进度解锁与存档含义。
- 不使用明显性别化的 SELA 形象。
- 不把界面改成霓虹赛博朋克或普通后台管理系统。
- 不让装饰纹理、动画或 SELA 抢占正文阅读空间。
- 不将拖拽设为唯一操作方式。
